`@skkuverse/vite-plugin-miniapp` is new. Its `skkuverseDevHost()` gives `vite dev` the host the app gives a page, so a miniapp or game page runs its in-app code path: `window.skkuverse` exists before the page's script, and each message the page posts prints one terminal line, `[skkuverse] page -> host <method> <params>`. A message the app would drop without a word throws from `postMessage` and names the method. `SKKUVERSE_PRESET` picks the host state (`granted`, `nothing-granted`, `no-host`, `late-host`, `slow-init` or `old-host:<version>`). The host grants a miniapp page only the miniapp methods and a game page only the game methods, and answers on a microtask, as the app does. A default build holds none of the host. `inject: 'always'` emits it as a hashed script for `vite preview` and browser tests. `miniapp-cli new` scaffolds a miniapp and a game that use it, and the miniapp template gains a button that calls `haptic('light')`. The templates name the plugin as `catalog:`, so a repository that upgrades the CLI and runs `new` adds `"@skkuverse/vite-plugin-miniapp": ^0.1.0` to its `pnpm-workspace.yaml` catalog first, or `pnpm install` fails with `ERR_PNPM_CATALOG_ENTRY_NOT_FOUND_FOR_SPEC`. `miniapp-cli ship` refuses to stage a build that holds the dev host, and names the file.
